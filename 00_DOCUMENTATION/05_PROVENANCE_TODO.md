# Provenance, droits et historique — à compléter

Les fichiers ont des noms d'import variés (`photo_...`, `document_...`, hashes et exports nommés). Aucun registre de provenance ou de licence n'était présent dans le dossier au moment du tri.

Avant toute exploitation commerciale ou mise en ligne publique, créer une fiche pour chaque asset ou famille d'assets :

- créateur / générateur / source ;
- date et contexte de création ;
- prompt ou fichier source si une génération IA est impliquée ;
- droits détenus par l'équipe ;
- références externes visibles ;
- autorisation pour jeu, animation, merch et usage commercial ;
- statut : validé, à vérifier, réservé à l'archive.

Points de vigilance visibles dans la bibliothèque :

- plusieurs crossovers ou clins d'œil à des personnages connus ;
- logos et noms de plateformes crypto ;
- photos de plush et de produits physiques ;
- assets dont le style semble provenir de sources différentes.

## Action recommandée

Ne pas supprimer les assets ambigus. Les conserver dans `99_REVIEW_TO_CANONIZE/` ou leur attribuer le statut `review` dans le futur catalogue, jusqu'à validation humaine.
